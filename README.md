# Kanban Tracker

**Панель управления задачами команды**

## Описание

Приложение для управления проектами и задачами команды, построенное на FastAPI и PostgreSQL.

### Основные функции

- Доска задач (канбан) с колонками: «Запланировано», «В работе», «Готово»
- Создание и редактирование задач
- Возможность добавлять участников к задачам
- Статистика выполненных задач

### Дополнительные функции

- Система комментариев в задачах
- Уведомления о новых задачах и изменениях

## Как запустить приложение

### Требования

Перед началом убедитесь, что у вас установлены:

- [Docker](https://docs.docker.com/get-docker/) (версия 20.10 или выше)
- [Docker Compose](https://docs.docker.com/compose/install/) (версия 1.29 или выше)

### Шаг 1: Клонирование репозитория

```bash
git clone https://github.com/borisboriov/kanban-tracker.git
cd kanban-tracker
```

### Шаг 2: Настройка переменных окружения

Скопируйте файл `.env.example` в `.env`:

```bash
cp .env.example .env
```

Файл `.env` содержит настройки по умолчанию. Вы можете изменить их при необходимости:

```env
# Main App Database
MAIN_DB_NAME=postgres
MAIN_DB_USER=user
MAIN_DB_PASSWORD=password
MAIN_DB_PORT=5432
MAIN_DB_HOST=localhost

# Services
MAIN_APP_PORT=8000
```

### Шаг 3: Запуск приложения с Docker Compose

Запустите все сервисы (база данных и приложение):

```bash
docker compose up -d
```

Команда `docker compose up -d` выполнит следующие действия:
- Скачает необходимые Docker образы (PostgreSQL)
- Соберет Docker образ приложения
- Запустит базу данных PostgreSQL
- Запустит главное приложение FastAPI

### Шаг 4: Применение миграций базы данных

После первого запуска необходимо применить миграции к базе данных:

```bash
docker compose exec main_app alembic upgrade heads
```

> **Примечание**: Используется `heads` (множественное число), так как в проекте может быть несколько ветвей миграций.

### Шаг 5: Доступ к приложению

Приложение теперь доступно по следующим адресам:

- **API**: http://localhost:8000
- **Интерактивная документация (Swagger UI)**: http://localhost:8000/docs
- **Альтернативная документация (ReDoc)**: http://localhost:8000/redoc
- **Проверка состояния**: http://localhost:8000/health

### Остановка приложения

Чтобы остановить приложение:

```bash
docker compose down
```

Чтобы остановить приложение и удалить все данные (включая базу данных):

```bash
docker compose down -v
```

## Разработка

### Работа с Alembic (миграции базы данных)

1. После изменения модели, генерируем миграцию:
```bash
docker compose exec main_app alembic revision --autogenerate -m "commit message"
```

2. Проверяем сгенерированный файл в `services/main-app/alembic/versions`

3. Применяем к базе данных:
```bash
docker compose exec main_app alembic upgrade heads
```

- `upgrade` - применить миграции
- `heads` - до всех самых новых миграций (используется при наличии нескольких ветвей)

### Запуск тестов

Для запуска тестов:

```bash
cd services/main-app
poetry run pytest
```

## Структура API

Приложение предоставляет следующие основные эндпойнты:

- `/api/v1/auth` - Регистрация и аутентификация
- `/api/v1/teams` - Управление командами
- `/api/v1/team_members` - Управление участниками команд
- `/api/v1/boards` - Управление досками
- `/api/v1/columns` - Управление колонками
- `/api/v1/tasks` - Управление задачами
- `/api/v1/task_members` - Управление участниками задач
- `/api/v1/comments` - Комментарии к задачам
- `/api/v1/statistics` - Статистика
- `/api/v1/notifications` - Уведомления

Полную документацию по API можно посмотреть по адресу http://localhost:8000/docs после запуска приложения.

## Архитектура проекта

### Требования к бэкенду

1. **Модель данных для основных функций проекта**

Минимальный набор таблиц:
- Таблица задача: идентификатор, заголовок, дата, описание, тип, ссылка на автора, ссылка на список пользователей, статус

2. **Модель данных для сервиса регистрации и аутентификации**

Поля пользователя: идентификатор, имя, фамилия, логин, пароль

3. **API для регистрации, авторизации и аутентификации**

Эндпойнты: регистрация, аутентификация, смена пароля, обновление токена

4. **API для управления задачами**

Операции: создание, удаление, редактирование, чтение (с пагинацией, фильтрами по типу, дате, автору, статусу)
